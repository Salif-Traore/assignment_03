The main thing I took from this assignment was how Streamlit’s rerun model works. An interaction with any widget will cause the whole script to be re-executed from the top, meaning a plain variable is reset to what it was at the start. That is why files_processed = 0 in process_files.py would not increment beyond one. It also put my use of widgets in a new light; whether it is st.text_input or st.button, they are all function calls that hand back their present value on each run, and before there has been any input that value is going to be None or False. One had to put a guard in place (if package_data:, for instance) to stop the app from crashing when there was nothing to act on.

I was also made aware of some nuances in process_file.py. An uploaded file comes in as raw bytes no matter what is in it, so an explicit .decode("utf-8") was required to turn it into a string for line splitting. Then there is the matter of the trailing newline in a text file leaving a blank final line that parse_packaging cannot make head or tail of and must be ignored.

process_files.py presented the most difficulty. There was an issue that called for two different solutions: I had to initialise files_processed, packages_processed and history in st.session_state just once, with a check like if "files_processed" not in st.session_state, to ensure they did not get wiped out by a rerun. On top of that, the real processing had to be put behind an if clicked and uploaded_file: condition using the return from st.button. Without it, the fact that the uploader holds its selection across reruns would mean the same file was being tallied over and over at the slightest change on the page.
